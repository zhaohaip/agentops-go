## 审核范围

仅阅读：

* `AGENTS.md`、`develop-spec` 下的开发规范及通用代码审核检查表；
* 开发实施计划中该 Phase 的目标、全部子任务及验收标准；
* 该 Phase 直接涉及的需求、架构设计、详细设计和公共契约；
* 该 Phase 的 Git Diff、相关实现、迁移、配置及测试。

审核类型：`PHASE_REVIEW`

## 重点确认

1. Phase 内全部子任务是否均已完成并满足各自验收标准，历史 Major 是否全部闭环。
2. 各模块接口、状态迁移、事务边界和数据契约是否一致，不存在仅单模块测试通过但集成链路失效的问题。
3. 主流程、异常流程、恢复流程及关键并发竞态是否通过真实依赖的集成测试验证。
4. 安全、幂等、版本与 Hash Guard、持久化一致性、资源生命周期及错误分类是否符合冻结设计。
5. 是否存在遗漏功能、重复实现、临时绕过、无关改动或对既有 Phase 能力的回归。
6. 测试是否覆盖 Phase 验收矩阵和关键失败路径，而非仅验证实现细节。

运行该 Phase 的相关测试、真实依赖集成测试、全量测试、构建和已有静态检查。无法执行的验证必须标记为 `BLOCKED`，不得视为通过。

## 输出要求

输出：

* 审核结论：`PASS`、`FAIL` 或 `BLOCKED`；
* 审核基线与范围；
* 按严重级别排列的 Findings；
* 各子任务及历史 Finding 的闭环情况；
* 测试、构建和静态检查证据；
* Phase 验收标准是否全部满足；
* 是否可以进入 Phase 提交或下一阶段；
* 范围外风险。

若结论不是 `PASS`，请给出每个阻塞问题的触发路径、实际影响、测试缺口和最小修复方向。
