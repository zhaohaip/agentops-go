## 任务信息

* 任务名称或编号：`<填写>`
* 任务目标：`<填写或引用任务文档>`
* 验收标准：`<填写或引用文档>`
* 变更范围：`<文件、目录、Commit 或分支范围>`

## 审核要求

1. 阅读并遵守项目中的：

    * `AGENTS.md`；
    * 通用代码审核检查表；
    * 当前任务对应的需求、设计和开发计划。

2. 本次审核类型为：

   ```text
   TASK_REVIEW
   ```

3. 以当前任务变更为中心，必要时检查直接相关的：

    * 调用方和实现方；
    * 公共接口与数据结构；
    * 配置、迁移和测试。

4. 判断当前实现是否：

    * 满足任务目标和验收标准；
    * 正确处理正常、异常和边界流程；
    * 遵守已有设计和公共契约；
    * 具有足够的测试；
    * 引入安全、并发、事务、数据一致性或兼容性问题。

5. 执行与当前任务相关的测试、构建和静态检查，并如实记录结果。无法执行时标记为 `BLOCKED`，不得视为通过。

6. 只进行审核，不修改代码，不扩大范围。与当前任务无关的既有问题单独列为范围外风险。

## 输出

请按照通用代码审核检查表输出：

* 审核结论：`PASS`、`FAIL` 或 `BLOCKED`；
* 审核范围；
* Findings；
* 验证结果；
* 验收标准是否满足；
* 是否可以进入 Git 提交环节；
* 范围外风险。

本结论只代表当前小任务，不代表所属阶段已经通过整体 Review。
